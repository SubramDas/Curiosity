# Data sources, datasets and grounding

## What data is used?

Revelink is an API-based application using existing models. **There is no custom model-training dataset, fine-tuning job, vector database or embedding-retrieval pipeline.** Data falls into live provider inputs, a small supplied source fixture, user-owned application records, and developer evaluation/design fixtures.

## What grounding means here

### Teacher answers

The teacher receives bounded user context plus the supplied notes. With eligible video analysis, it also sends the public video URL to Gemini. There are three output-basis labels:

| Basis            | Evidence supplied                                               | What the code checks                                                                                                       | What it does not prove                                                                                     |
| ---------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `checked-notes`  | Developer-prepared CUDA notes and source IDs                    | Returned source IDs must be among supplied IDs; links come from the fixture                                                | That every sentence in the answer is supported, or that a broad curriculum has been reviewed               |
| `video-analysis` | Public video URL, validated metadata/duration and user question | Video analysis was used; question is labeled related; timestamps must fit duration and include explanation/evidence fields | That the creator is correct or that the proposed segment actually answers the question; manually verify it |
| `general`        | Model knowledge and conversation/title context                  | Validated output structure; title-only mode cannot return an accepted timestamp                                            | Independent factual grounding, live web verification, or knowledge of exact video contents                 |

The basis is selected from returned source IDs and analysis/relation state; it is an **evidence category, not an accuracy score**. A mixed answer can contain both supported and general statements. Source-ID validation does not check claim-by-claim entailment.

The prompt asks the model to avoid invented references, current prices/rankings/news and unsupported timestamps. The backend rejects unknown source IDs and discards invalid timestamp structures. Those protections reduce particular failure modes; they do not eliminate hallucinations. Current web search/fact-checking is not enabled.

When video input is unavailable, the UI can receive `title-only` or `none` context with notices. Unsupported video-input HTTP 400 responses permit one text fallback, consuming another chat attempt. Other network/provider failures are reported, not silently converted into verified answers. Recommendations use actual YouTube results rather than model-invented video IDs; their relevance still needs review.

### Topic classification

1. Fetch real public, embeddable video metadata on the server. Browser-supplied titles/labels are not accepted as classification evidence.
2. Gemini extracts a focused topic/aliases from bounded title, description, channel, tags and category evidence.
3. Wikidata supplies bounded candidate entities and selected relationship types.
4. Gemini resolves against supplied candidates; a QID must come from those candidates. Unmatched concepts remain provisional.
5. A primary Universe and direct substantial overlaps are used for placement.

This is **metadata-grounded topic inference**, not full video-content fact-checking. A Wikidata match does not certify teaching quality, educational intent, or factual accuracy. Temporary Wikidata failures can return provisional results.

### Search and recommendations

Gemini evaluates learning intent and video purpose from supplied query/metadata. Ambiguous queries can produce learning choices; entertainment queries can produce educational alternatives. Failed checks should produce errors rather than unchecked results on the guarded search path.

YouTube ranking, recent/popular learning discovery and reuse of saved searches drive current recommendations. There is no trained personalized recommender demonstrated here. Break clips are checked for topical relatedness, but need not themselves be lessons. No Instagram API, private YouTube-account ingestion or web scraping pipeline is implemented.

## Storage, expiry and data flow

| Data                                        | Local / hosted storage                                                               | Lifetime or boundary                                                                                                                       |
| ------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| YouTube search pages / playable details     | `.local-data/youtube-cache.json` / Firestore `curiosity_cache`                       | Six hours; Trending one hour                                                                                                               |
| Query-intent decisions                      | Same provider cache                                                                  | Six hours; query/goal, model and policy affect the key                                                                                     |
| Video-purpose decisions                     | Same provider cache                                                                  | 24 hours; metadata, model, policy and break topic/purpose affect reuse                                                                     |
| Extracted topics / accepted classifications | `.local-data/classification-cache.json` / Firestore `curiosity_classification_cache` | 30 days; video ID, bounded metadata fingerprint, model and policy affect reuse                                                             |
| Temporary Wikidata-outage classification    | Classification cache                                                                 | Five minutes; accepted first-stage topic extraction can still be reused                                                                    |
| Wikidata candidates                         | Classification cache                                                                 | Six hours                                                                                                                                  |
| Approved public search catalog              | Provider cache                                                                       | Bounded 24-hour records; classification alone does not extend educational approval                                                         |
| Related-break permits / results             | Provider cache                                                                       | Six hours; frontend permit reuse is limited to five hours; at most three results                                                           |
| Provider daily usage                        | `.local-data/usage.json` / Firestore `curiosity_usage`                               | Per UTC-day counters; persists across restart/redeploy. Code does not promise a scheduled deletion lifetime for historical hosted counters |
| Guest topics / progress / timer             | Browser local/session storage                                                        | Browser-controlled persistence and feature-specific bounds; clearing browser data removes it                                               |
| Account records                             | Supabase tables with RLS                                                             | Persistent user-owned app data; comprehensive deletion/export workflows remain wider-release work                                          |
| Current chat conversation                   | Frontend state; bounded history sent with requests                                   | No app database chat-history persistence implemented; refresh/new conversation/account changes clear conversation state                    |

Cache capacity eviction can remove records before their TTL. Local caches default to 500 entries; hosted caches to 400 per namespace. Existing entries retain original expiry when policy changes; the longer classification TTL applies to newly generated results. Cached metadata may delay noticing a creator's metadata change until refresh. Firestore TTL deletion is asynchronous; app expiry checks control whether data is served.

Cache keys are hashed, **not encrypted or anonymized**. Some derived cache payloads (for example generated decision text and break-topic titles) can contain input-related text. Generated recommendation queries may be cached. Do not enter sensitive information: user questions/history and applicable source/video context are sent to external model services; search terms are sent to YouTube and extracted topic terms to Wikidata. Provider retention/usage is governed separately by the configured accounts and provider terms. No promise of zero external retention is made.

YouTube/Gemini secrets stay in backend configuration/Secret Manager, not browser bundles. The browser intentionally receives the Supabase URL and publishable/anon key. User records use verified server identity and RLS; public caches are separate. Automated permission tests use simulated services and do not establish a fresh live two-account security audit.

No external dataset download is required for local guest use. Do not describe these tiny fixtures as a large corpus, fine-tuning data or statistically validated test set. No training/test split exists because no training is performed.

External videos/metadata, NVIDIA documentation and Wikidata content retain their respective ownership and applicable terms. Source links and small developer paraphrases are included for provenance; this repository does not grant redistribution rights to third-party videos or documents. Review applicable terms before broader reuse. No external corpus has been relicensed as Revelink-owned content.

For reviewed evaluation, freeze expected labels before running cases, identify reviewer/date, audit actual metadata/video evidence, and report sample size plus review coverage. The [benchmark guide](../../experiments/benchmarks/README.md) defines the scoring fields and denominators. See [results](RESULTS.md) for what has actually been measured.
